# Database Schema - Classroom Chat

This document describes the tables defined in `backend/application/models/` (SQLAlchemy ORM). The
table list below was taken from `db.metadata.tables`; columns were read from the model files.
When in doubt the models are the source of truth.

## 1. Overview

- **Development / testing**: SQLite (`DEV_DATABASE_URI`, default `sqlite:///dev_users.db`).
- **Production**: `DATABASE_URL`, set by `deploy.yml` to the SQLite file `backend/instance/prod_users.db`.
- **Schema management**: production schema changes go through Alembic (`backend/migrations/`,
  applied by `deploy.sh` with `flask db upgrade`, followed by `python -m tools.migrate_classroom`).
  `db.create_all()` is only run outside production (`application/__init__.py`).

Tables: `users`, `achievement`, `user_achievement`, `user_certificate`, `challenges`,
`challenge_logs`, `classrooms`, `user_classrooms`, `courses`, `course_instances`, `conversations`,
`conversation_users`, `messages`, `duck_trade_log`, `duck_transactions`, `projects`, `skills`,
`notes`, `session_logs`, `configuration`, `banned_words`, `ai_settings`.

---

## 2. Users and portfolio

### 2.1 `users` (`user.py`)
- **Identity**: `id`, `username` (unique; the attribute is `_username`), `nickname`, `slug` (unique, generated by a `before_insert` event), `bio`
- **Auth / status**: `password_hash`, `is_admin`, `is_approved`, `is_online`, `ip_address`, `created_at`
- **Profile**: `profile_picture` (default `Default_pfp.jpg`)
- **Gamification**: `duck_balance`, `earned_ducks`, `packets`, `last_daily_duck`, `last_achievement_evaluation`
- Relationships with `cascade="all, delete-orphan"`: skills, projects, achievements, certificates, notes.

### 2.2 `projects` (`project.py`)
`id`, `name`, `description`, `link`, `user_id` (FK users), `teacher_comment`, `code_snippet`,
`github_link`, `video_url`, `video_transcript`, `image_url`.

### 2.3 `skills` (`skill.py`)
`id`, `name`, `user_id` (FK users), `category` (language/tool/concept), `icon`, `proficiency` (1 bronze, 2 silver, 3 gold).

### 2.4 `notes` (`note.py`)
`id`, `user_id` (FK users), `filename`, `created_at`.

### 2.5 `session_logs` (`session_log.py`)
`id`, `user_id` (FK users), `start_time`, `end_time`, `last_seen`.

---

## 3. Chat

### 3.1 `conversations` (`conversation.py`)
`id`, `title`, `creator_id` (FK users, SET NULL), `classroom_id` (FK classrooms, RESTRICT),
`is_locked`, `slow_mode_delay` (seconds), `created_at`.

### 3.2 `conversation_users`
Association table (many-to-many) between `conversations` and `users`; both FKs cascade on delete.

### 3.3 `messages` (`message.py`)
`id`, `conversation_id` (FK, CASCADE), `user_id` (FK, CASCADE), `content`, `message_type`
(enum `text` / `link` / `code_snippet`), `is_struck`, `created_at` (indexed), `edited_at`, `deleted_at`.

---

## 4. Classrooms and courses

- **`classrooms`** (`classroom.py`): `id` (string), `name`, `language`, `url`, `course_id`, `created_at`.
- **`user_classrooms`**: association table between `users` and `classrooms` with `enrolled_at`.
- **`courses`** (`course.py`): `id` (string), `name`, `domain`, `description`, `is_active`, `created_at`, `default_challenge_value`.
- **`course_instances`** (`course_instance.py`): `id` (string), `classroom_id` (FK classrooms), `course_id` (FK courses), `created_at`.

---

## 5. Challenges, achievements and ducks

- **`challenges`** (`challenge.py`): `id`, `name` (unique), `slug` (unique), `domain`, `difficulty`, `value`, `is_active`, `created_at`, `course_id`, `classroom_id` (FK classrooms, SET NULL), `description`.
- **`challenge_logs`** (`challenge_log.py`): `id`, `username` (indexed string, **not** a foreign key), `domain`, `challenge_slug`, `timestamp`, `course_id`, `course_instance`, `helper`.
- **`achievement`** (`achievements.py`): `id`, `slug` (unique), `name`, `type`, `reward`, `description`, `requirement_value`, `source`.
- **`user_achievement`**: `id`, `user_id` (FK users), `achievement_id` (FK achievement), `earned_at`.
- **`user_certificate`** (`user_certificate.py`): `id`, `user_id` (FK users), `achievement_id` (FK achievement), `url`, `file_path`, `submitted_at`, `reviewed`, `reviewed_at`.
- **`duck_trade_log`** (`duck_trade.py`, model `DuckTradeLog`): `id`, `username` (FK `users.username`), `digital_ducks`, `bit_ducks` (JSON), `byte_ducks` (JSON), `status` (pending / approved / rejected), `timestamp`.
- **`duck_transactions`** (`duck_transaction.py`): `id`, `user_id` (FK users), `amount`, `reason`, `timestamp`.

---

## 6. Configuration and moderation

- **`configuration`** (`configuration.py`): `ai_teacher_enabled`, `message_sending_enabled`, `duck_multiplier`.
- **`banned_words`** (`banned_words.py`): `id`, `word` (unique), `added_on`, `reason`, `active`.
- **`ai_settings`** (`ai_settings.py`): `id`, `key`, `value`.

---

## 7. Relationships summary

- User to projects, skills, notes, achievements, certificates: one-to-many.
- Conversation to messages: one-to-many; users to conversations: many-to-many via `conversation_users`.
- Users to classrooms: many-to-many via `user_classrooms`; classroom to conversations and course instances: one-to-many.
- Achievement to user achievements and certificates: one-to-many.

## 8. Integrity and hooks

- **Slugging**: a `before_insert` event on `User` generates a unique URL-friendly slug.
- **Cascades**: user-owned rows (skills, projects, achievements, certificates, notes) use `cascade="all, delete-orphan"`; messages and `conversation_users` cascade from their parents.
